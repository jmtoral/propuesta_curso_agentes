Hooks, verificación y GitHub Pages.

El problema

El agente se equivoca con total seguridad.

Errores típicos
Dice «listo»sin haber corrido el programa.
Cuenta malporque se saltó filas que no entendió.
Rellenalo que falta con algo que suena verosímil.
Cambiael formato de un archivo que otro paso necesita.
Verificar a mano

El oficio de siempre

  • Muestreo: filas al azar contra la fuente original.
  • Totales: ¿la suma de las partes da el total?
  • Límites: ¿hay fechas fuera del periodo, valores negativos, nombres vacíos?

Lo que revisan siempre igual se puede automatizar.

Hooks

Controles que corren solos

  • Un hook es un comando que Claude Code corre en un momento fijo, sin que nadie lo pida.
  • Momentos útiles: antes de usar una herramienta, después de editar un archivo, y cuando el agente dice que terminó.
  • Se configuran en .claude/settings.json, o con el menú /hooks.
La diferencia

CLAUDE.md pide. El hook obliga.

Ejemplo · .claude/settings.json 
{
  "hooks": {
    "Stop": [
      { "hooks": [
        { "type": "command", "command": "python validar.py" }
      ] }
    ]
  }
}

Cada vez que el agente diga «terminé», corre validar.py. Si el programa sale con código 2, el agente no puede terminar: recibe el error y tiene que arreglarlo.

Práctica · 30 min

Su validador

  1. Pídanle al agente un validar.py que revise el CSV: sin filas vacías, fechas dentro del mes, al menos un turno por conferencia.
  2. Configuren el hook Stop.
  3. Rompan el CSV a propósito y pídanle cualquier cosa al agente. ¿Lo detuvo el hook?
Publicar
Práctica · 30 min

GitHub Pages

  1. Pídanle al agente una página docs/index.html con sus tablas y una gráfica.
  2. Commit y push.
  3. En GitHub: Settings → Pages → Deploy from a branch → main y carpeta /docs.
  4. En un par de minutos su página está en usuario.github.io/mananeras.

Lo publicado es público. Solo datos públicos.
